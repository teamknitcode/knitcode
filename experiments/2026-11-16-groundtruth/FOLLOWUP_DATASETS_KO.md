# 후속 논문 데이터셋 검토

PyCG 외의 독립적인 실험 대상을 추가하되, 완전한 정답과 특정 실행에서 관찰한 호출 집합을 구분한다. 아래는 문헌·공개 저장소를 확인한 후보이며 아직 KnitCode 실행 결과는 아니다.

**후속 진행:** Jarvis 공식 artifact의 소스와 EA 정답을 확보해 sqlparse·furl 평가를 완료했다. 공통 앱 함수 범위의 호출 중심 보강에서 F1 향상을 확인했으며, 전체 추적 비용·제한 초과도 기록했다. 아래의 미검증 상태는 후보 조사 당시 기록이다. 결과: `experiments/2026-11-16-jarvis/REPORT_NOTION_KO.md`.

| 후보 | 정답의 성격 | 활용 판단 |
|---|---|---|
| Jarvis | 실제 앱 6개. 테스트 실행 기록을 만든 뒤 사람이 앱 함수를 검토해 누락 관계 보강 | 정확도 비교의 우선 후보 |
| DyPyBench | 50개 프로젝트의 테스트와 DynaPyt 실행 호출 그래프 | 실행 경로 검증·규모·비용 평가에 적합. 전체 정밀도 정답으로 쓰지 않음 |
| PyAnalyzer macro D | 54개 프로젝트의 실행 기록에서 얻은 함수 의존 관계 8,233개 | 추가 후보. 저장소 안내상 대규모 원본 자료는 저자에게 요청해야 함 |

## 우선 실험: Jarvis

논문은 bpytop·sqlparse 등 6개 실제 앱과 총 5,653개 함수·20,085개 호출 관계의 정답을 설명한다. 이 합계에는 라이브러리 범위가 포함되므로 앱 자체 규모로 해석하지 않는다. 앱 전체(E.A.)와 진입점 중심(A.A./A.W.) 평가는 범위와 채점 방식이 다르다.

1. 공개 `data.zip`의 GT·소스·버전·진입점·평가 스크립트부터 검증한다.
2. 실행 가능한 대상의 테스트와 분석 범위를 정답을 보며 선택하지 않고 고정한다.
3. 같은 범위로 정적 단독 / 정적+호출 중심 / 정적+전체 추적을 비교한다.
4. 정밀도·재현율·F1·시간과 함께, 미실행 정답·외부 호출·매핑 실패를 따로 보고한다.

기존 사이트의 `Jarvis.zip` 링크는 조회 시 404였으나 공식 GitHub 저장소에는 `data.zip`이 확인됐다. 실제 압축 내부 구성과 재현 가능성은 아직 미검증이다.

## 실행 기반 정답의 주의점

보강에 사용한 실행 호출을 그대로 정답으로 사용하면 개선이 자명해지는 순환 평가가 된다. DyPyBench 등을 사용할 때는 보강용 테스트와 평가용 테스트를 분리하고, 전체 정확도 대신 평가 실행에서 관찰된 관계의 재현율·추가 검증 수를 측정한다. 미관찰 간선을 곧바로 FP로 판단하지 않는다.
