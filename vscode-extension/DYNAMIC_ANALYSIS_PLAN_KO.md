# 동적 분석 기능 추진안 — 팀 회의용

## 1. 목표

1차 정적 분석 시각화를 바탕으로, **선택한 테스트에서 실제로 관찰된 호출 관계**를 기존 그래프에 표시한다.

- 정적 분석: 실행하지 않고 가능한 호출 관계를 추론
- 동적 분석: 테스트를 실행하며 실제 호출 관계를 관찰
- 실행되지 않은 경로도 있으므로, 미관찰 호출을 오류로 판단하지 않는다.

## 2. 기술 방향

**`sys.setprofile`을 우선 검토하고, DynaPyt는 비교·확장 후보로 둔다.**

| 후보 | 활용 방향 |
|---|---|
| `sys.setprofile` | 기존 `calltrace_plugin.py`를 재사용해 호출 관계 수집부터 구현 |
| DynaPyt | 소스 계측 기반. 향후 변수 접근·분기 등 세밀한 분석이 필요할 때 검토 |

성능 우위는 미리 단정하지 않는다. DyPyBench의 프로젝트당 평균 215분은 해당 실험의 호출 그래프 수집 실행 시간이며, 모든 동적 분석의 고정 비용은 아니다. [논문 §4.1.2](https://arxiv.org/html/2403.00539v1#S4.SS1.SSS2)

## 3. 진행 순서

1. **성능·정확성 확인** → 같은 테스트를 일반 실행 / `sys.setprofile` / DynaPyt로 실행해 시간·메모리·수집 호출 비교
2. **최소 기능 구현** → 기존 `trace.json`을 불러와 정적 그래프의 함수와 연결
3. **화면 표시** → 정적·실행 모두 확인 / 정적에서만 발견 / 실행에서만 발견을 구분하고 실행 관찰 필터 제공
4. **실행 기능 연결** → 확장에서 Python 환경·테스트를 선택해 실행하고 결과 저장

## 4. 첫 버전 범위와 회의 결정사항

- 첫 버전은 **선택한 테스트의 호출 관계 확인**까지 진행한다.
- 호출 횟수·소요 시간·실행 순서·실제 인자값 수집은 후속 과제로 둔다. 현재 기록은 중복을 제거한 호출 집합이다.
- 코드 버전과 실행 성공·실패를 함께 기록해 결과의 적용 범위를 표시한다.
- 회의에서 **비교 실험 대상, 담당자, 일정, 허용 실행 시간**을 정한다. 실험 결과로 기본 수집 방식을 확정한다.
