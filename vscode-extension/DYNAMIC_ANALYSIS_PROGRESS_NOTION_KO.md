## 1. 추진 방향

동적 분석은 실제 실행 시간에 추적 비용이 더해지므로, 선택한 테스트·시나리오를 대상으로 사용한다.

| 역할 | 정적 분석 | 동적 분석 |
|---|---|---|
| 방법 | 실행 없이 코드 구조와 객체 흐름 해석 | 실제 실행에서 호출 관찰 |
| 활용 | 전체 호출 후보와 프로젝트 구조 제공 | 실제 호출 대상 확인, 놓친 호출 추가 |
| 한계 | 런타임에 결정되는 관계를 놓칠 수 있음 | 실행하지 않은 경로는 확인 불가 |

예를 들어 정적 분석이 `A → B 또는 C`를 예측하고 실행에서 B가 관찰되면, **B에 실행 근거를 붙이고 C는 후보로 유지**한다. 미관찰은 오류의 증거가 아니다.

## 2. 기술 선택과 비용 판단

- **`sys.setprofile` 우선 검증:** 호출 관계 보강에 맞고 기존 수집 코드를 활용할 수 있다.
- **DynaPyt는 비교·확장 후보:** 소스 계측을 통해 변수 접근·연산·분기 등 세밀한 분석을 구성할 수 있다.
- **속도 우위는 아직 미확정:** 같은 입력과 수집 범위로 측정해야 한다. 내부 호출만 저장해도 외부 이벤트를 걸러내는 비용은 남는다.

DyPyBench 논문의 **프로젝트당 평균 215분**은 DynaPyt로 50개 프로젝트의 테스트를 실행하며 호출 그래프를 수집한 실험 수치다. 모든 동적 분석의 고정 비용이나 순수 추가 비용을 뜻하지 않는다. [논문 §4.1.2](https://arxiv.org/html/2403.00539v1#S4.SS1.SSS2)

## 3. 인계 PR에서 확인한 구현

대상: [PR #4 — 동적 분석 sys.profile](https://github.com/teamknitcode/knitcode/pull/4) · 작성자: `kyum0731`

기존 pytest 검증용 `calltrace_plugin.py`는 중복을 제거한 호출 집합을 기록한다. 이번 PR은 **별도 수집기와 정적 그래프 연결 계층**을 추가해 기능을 확장했다.

| 구성 | 구현 내용 |
|---|---|
| `dynamic_analysis.py` | 스크립트·모듈 실행, 실행 기록 저장·비교 |
| `profile_collector.py` | 호출 관계·이벤트 수·인자 및 반환 타입 수집 |
| `python_execution.py` | 줄·분기 커버리지와 변수 접근 수집 |
| `runtime_bridge.py` | 소스 해시를 검증해 정적 노드에 실행 기록 연결 |
| `main.py --dynamic-trace` | 정적 결과를 보존하면서 `hybrid_graph.json` 생성 |

관계는 `confirmed`(정적·실행 일치), `additional`(실행에서만 발견), `unmapped`(연결 불가), `scope_entry`(모듈·클래스 본문 진입)로 구분한다. **VS Code 화면 연동은 아직 남아 있다.**

기본 모드는 `sys.setprofile`과 줄·opcode용 `sys.settrace`를 함께 사용한다. `--calls-only`는 줄·opcode 추적을 끄고 호출·타입을 수집하므로, 보조 분석의 첫 실험 대상으로 삼는다. 호출 이벤트 수에는 제너레이터·코루틴 재개도 포함된다.

## 5. 다음 작업

### 후속 실험 완료 (2026-11-15)

Requests의 오프라인 테스트 27개를 3회씩 측정했다. 중앙값은 일반 실행 **0.152초**, calls-only **0.907초**, 전체 추적 **1.974초**였다. calls-only는 전체 추적보다 약 54% 짧았지만 일반 실행보다 약 6배 걸렸다. 짧은 테스트에 대한 결과이며 전체 프로젝트 비용으로 일반화하지 않는다.

동적 호출 예제에서 정적 분석이 놓친 `getattr` 호출을 보강했다. Requests의 추가 관계 17개 중 16개는 테스트 함수에서 출발했고, 나머지 1개도 테스트 콜백이었다. 제품 코드의 보완 효과와 테스트 관찰 결과를 구분해야 한다.

실험 중 `--python`의 가상환경 링크를 해제해 설치 패키지를 찾지 못하는 문제를 추가 수정했다. 전체 pytest는 수집 경로를 지정한 설정에서 **569개 통과·7개 건너뜀·41개 subtest 통과**를 확인했다. 현재 작업 트리에는 이전 회귀 검사·문서가 제거된 차이도 있어, 이를 덮어쓰지 않고 수정 패치를 분리했다.

상세 결과: `experiments/2026-11-15-pr4-handoff/BENCHMARK_KO.md`. 원격 push·merge와 화면 연동은 아직 진행하지 않았다.

1. **PR 반영:** 수정 커밋을 인계 PR에 적용하고 CI·팀 검토 확인
2. **비용 실험:** 같은 테스트를 일반 실행 / `--calls-only` / 기본 전체 추적으로 실행해 시간·메모리·결과 크기 비교
3. **보완 효과 평가:** 정적으로 확인된 호출, 실행에서 추가 발견한 호출, 연결하지 못한 호출을 구분해 원인 검토
4. **시각화 연결:** 기존 그래프에 실행 근거와 실행 관찰 필터 제공

실행 결과는 **대상 코드 버전·입력·성공/실패·수집 완전성**과 함께 관리한다. 타입 관찰은 타입 적합성 증명이 아니며, 미관찰 정적 간선을 자동 삭제하지 않는다.

### 정답 기반 후속 평가 (2026-11-16)

공식 PyCG 정답을 가진 autojump·asciinema·Fabric에서 정적 단독, 정적+호출 중심, 정적+전체 추적을 비교했다. autojump·asciinema는 점수가 같았고, Fabric은 정답 호출 1개와 정답에 없는 관계 3개가 추가돼 재현율은 58.79%→59.06%, F1은 71.79%→71.66%였다.

**현재 합집합 방식으로 F1 향상은 확인하지 못했다.** 두 추적 방식의 결합 호출 집합은 같았으며, 전체 추적은 약 18~27% 더 오래 걸렸다. 다음 과제는 누락 경로의 실행 범위와 정답에 없는 추가 관계를 분석하는 것이다. 테스트 범위·정답 포함 정책을 함께 해석해야 한다.
